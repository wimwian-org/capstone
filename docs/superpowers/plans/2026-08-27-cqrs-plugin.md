# CQRS Plugin and Real :cache Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix the `:cache` plugin to use a real, supervised Nebulex cache instead of its dead `:persistent_term` stub, and add a new `:cqrs` plugin (Command/Query/Dispatcher, UUIDv7 primary keys, a short-term cache-reservation uniqueness check backed by real DB constraints).

**Architecture:** Both plugins are hand-authored project trees under `priv/meta/<name>_component/` (copies of `priv/meta/baseline_api/` with edits), diffed automatically by `mix capstone.plugin.derive <name>` into `priv/meta/meta_<name>/manifest.exs`. No new capstone tooling — every task here is either editing a component tree by hand, running an existing mix task, or writing a test.

**Tech Stack:** Elixir 1.20, Phoenix 1.8, Ecto 3.13, Nebulex 3.0 (`Nebulex.Adapters.Local`), Uniq 0.6 (`Uniq.UUID`, an `Ecto.ParameterizedType`).

**Spec:** `docs/superpowers/specs/2026-08-27-cqrs-plugin-design.md`

## Global Constraints

- Both plugins are built via the existing pipeline: hand-edit `priv/meta/<name>_component/`, then `mix capstone.plugin.derive <name>` diffs it against its baseline into `priv/meta/meta_<name>/manifest.exs`. Never hand-edit files under `priv/meta/meta_<name>/` directly — they are `derive`'s generated output and get overwritten.
- `mix.exs` deps are added directly to the component's own `mix.exs` `deps/0` list — `Capstone.Plugin.MixChanges` diffs them structurally and captures them into the manifest's `deps:` key automatically. Never hand-edit a manifest's `deps:` list.
- A supervision-child edit in `application.ex` is auto-detected by `Derive.added_child/2` ONLY when: (a) exactly one child is added per component (never two at once), (b) it is appended as the literal last element of the `children` list, and (c) nothing else in the file changes — not even the stale `# Start to serve requests, typically the last entry` comment above the Endpoint entry. Touching anything else falls through to a `:manual` anchor, which is a silent-conflict-marker risk (see `plugin_lifecycle_test.exs`'s moduledoc).
- A `config/config.exs` edit is auto-detected as `:before_import` when the new `config :app, ...` block is inserted immediately before the trailing `import_config "#{config_env()}.exs"` line, with nothing else in the file touched.
- `Uniq.UUID` is an `Ecto.ParameterizedType`, not plain `Ecto.Type`, and defaults to `version: 4`. Every schema that wants UUIDv7 primary keys must declare `@primary_key {:id, Uniq.UUID, autogenerate: true, version: 7, type: :binary_id}` — both `version: 7` and `type: :binary_id` are required, not decorative (verified against the `uniq` 0.6.3 source).
- Nebulex 3.0's `Nebulex.Cache` callbacks are return-wrapped: `put_new/3` returns `{:ok, boolean}`, `get/3` (key, default, opts) returns `{:ok, value}`, `put/3` returns `:ok | {:error, reason}`, `delete/2` (key, opts) returns `:ok` (verified against `nebulex` 3.0.4's hexdocs).
- `:cqrs` is `derived_from: :api`, independent of `:cache` — a project must be able to apply `:cqrs` without `:cache`. Neither plugin lists the other in `requires`/`conflicts`.
- `Dispatcher.dispatch/2` only supports the create path (`Repo.insert/1`) in v1 — no update support. This is documented in the plugin's README contribution, not silently unsupported.
- No fixture Ecto schema or migration is ever added to `priv/meta/cqrs_component/` — capstone doesn't know a consuming project's schemas, and a migration that creates an unrelated fixture table would be genuine noise in every project that applies `:cqrs`. Shipped unit tests (inside `cqrs_component/test/cqrs/`) use only embedded schemas (no migration needed) or a pre-populated cache key (no schema needed at all). The one test that needs a real DB-backed schema, migration and table (the concurrent-dispatch race) lives entirely in capstone's own `test/integration/`, writing its fixtures directly into a freshly bootstrapped temp project — never into `cqrs_component`.
- A local Postgres is running (`postgres`/`postgres`, `localhost`) — `priv/meta/baseline_api/config/test.exs` already points at it, and every derived project (including `cqrs_component`) inherits that config unchanged.
- `priv/meta/baseline_api/mix.exs`'s `aliases/0` already defines `test: ["ecto.create --quiet", "ecto.migrate --quiet", "test"]` — running `mix test` inside any generated/derived project (including the toolchain integration test's temp project) creates and migrates its database automatically. No separate `ecto.create`/`ecto.migrate` calls are needed.

```elixir
defmodule NewApiApp.Cache do
  @moduledoc """
  A read-through cache for NewApiApp, backed by `NewApiApp.Cache.Store`.
  """

  alias NewApiApp.Cache.Store

  @miss :__cache_miss__

  @doc "Fetches `key`, computing it with `fun` on a miss. Never expires."
  def fetch(key, fun) when is_function(fun, 0), do: fetch(key, :infinity, fun)

  @doc "Fetches `key`, computing it with `fun` on a miss. Expires after `ttl` ms."
  def fetch(key, ttl, fun) when is_function(fun, 0) do
    case Store.get(key, @miss, []) do
      {:ok, @miss} ->
        value = fun.()
        :ok = Store.put(key, value, ttl: ttl)
        value

      {:ok, value} ->
        value
    end
  end
end
```

```elixir
defmodule NewApiApp.CQRS.UniqueCheck do
  @moduledoc """
  Short-term cache reservation plus DB-constraint validation for a
  command's declared unique-field groups
  (`c:NewApiApp.CQRS.Command.unique_fields/0`).

  The cache is a fast-reject optimization and a race guard between the
  reservation check and the write landing — the DB's own unique index,
  wired via `validate_unique_constraints/2`, is the ground truth.
  """

  alias NewApiApp.CQRS.Cache

  @ttl :timer.seconds(30)

  @doc """
  Reserves every field group's cache key for `changeset`'s current values.
  Returns `{:ok, changeset, reserved_keys}` if every group was free, or
  `{:error, changeset}` (with a "has already been taken" error on the first
  field of the taken group) if any group was already reserved — releasing
  whatever this attempt had already reserved before returning.
  """
  @spec reserve(Ecto.Changeset.t(), [[atom()]]) ::
          {:ok, Ecto.Changeset.t(), [term()]} | {:error, Ecto.Changeset.t()}
  def reserve(changeset, unique_fields) do
    schema = changeset.data.__struct__

    Enum.reduce_while(unique_fields, {:ok, changeset, []}, fn group, {:ok, cs, reserved} ->
      key = cache_key(schema, group, cs)

      case Cache.put_new(key, true, ttl: @ttl) do
        {:ok, true} ->
          {:cont, {:ok, cs, [key | reserved]}}

        {:ok, false} ->
          Enum.each(reserved, &Cache.delete(&1, []))
          {:halt, {:error, Ecto.Changeset.add_error(cs, hd(group), "has already been taken")}}
      end
    end)
  end

  @doc "Releases every field group's reservation for `changeset`. Called after a lost race."
  @spec release(Ecto.Changeset.t(), [[atom()]]) :: Ecto.Changeset.t()
  def release(changeset, unique_fields) do
    schema = changeset.data.__struct__
    Enum.each(unique_fields, &Cache.delete(cache_key(schema, &1, changeset), []))
    changeset
  end

  @doc """
  Adds `Ecto.Changeset.unique_constraint/3` for every group, named to match
  the default name Ecto's own `unique_index/2` migration helper produces
  for that same field list — call this from inside a command's
  `changeset/1`. The matching migration needs no explicit `:name` option;
  just declare the index over the same fields, in the same order, as the
  group.
  """
  @spec validate_unique_constraints(Ecto.Changeset.t(), [[atom()]]) :: Ecto.Changeset.t()
  def validate_unique_constraints(changeset, unique_fields) do
    source = changeset.data.__struct__.__schema__(:source)

    Enum.reduce(unique_fields, changeset, fn group, cs ->
      name = :"#{source}_#{Enum.join(group, "_")}_index"
      Ecto.Changeset.unique_constraint(cs, hd(group), name: name, fields: group)
    end)
  end

  defp cache_key(schema, group, changeset) do
    {schema, group, Enum.map(group, &Ecto.Changeset.get_field(changeset, &1))}
  end
end
```

    use Ecto.Schema

      changeset = Fixture.changeset(%{email: unique_email(), org_id: 1, username: "alice"})

      assert {:ok, ^changeset, reserved} =
               UniqueCheck.reserve(changeset, [[:email], [:org_id, :username]])

      assert length(reserved) == 2
    end

    test "fast-rejects and releases its own reservations when a later group is taken" do
      taken_username = "taken-#{System.unique_integer([:positive])}"
      email = unique_email()

      first = Fixture.changeset(%{email: unique_email(), org_id: 1, username: taken_username})
      assert {:ok, _cs, _reserved} = UniqueCheck.reserve(first, [[:org_id, :username]])

      # The :email group, reserved before the :org_id/:username group lost
      # the race, must have been released — not left dangling.
      retry = Fixture.changeset(%{email: email, org_id: 99, username: "someone-else"})
      assert {:ok, _cs, _reserved} = UniqueCheck.reserve(retry, [[:email]])
    end
  end

  describe "release/2" do
    test "frees every group's key so a later reserve for the same values succeeds" do
      changeset = Fixture.changeset(%{email: unique_email(), org_id: 1, username: "bob"})
      unique_fields = [[:email]]

      assert {:ok, _cs, _reserved} = UniqueCheck.reserve(changeset, unique_fields)
      assert UniqueCheck.release(changeset, unique_fields) == changeset
      assert {:ok, _cs, _reserved} = UniqueCheck.reserve(changeset, unique_fields)
    end
  end

  describe "validate_unique_constraints/2" do
    test "adds one unique_constraint per group, named after the fields it covers" do
      changeset = Fixture.changeset(%{email: unique_email(), org_id: 1, username: "carol"})

      validated =
        UniqueCheck.validate_unique_constraints(changeset, [[:email], [:org_id, :username]])

               %{type: :unique, field: :email, constraint: email_constraint},
               %{type: :unique, field: :org_id, constraint: org_username_constraint}
             ] = validated.constraints

      assert email_constraint =~ "email"
      assert org_username_constraint =~ "org_id_username"

      end)

```elixir
defmodule NewApiApp.CQRS.Dispatcher do
  @moduledoc """
  Single entry point for CQRS commands and queries.

  `dispatch/2` only supports the create path (`Repo.insert/1`) in this
  version — a command whose changeset targets an existing record is out of
  scope.
  """

  alias NewApiApp.CQRS.UniqueCheck
  alias NewApiApp.Repo

  @spec dispatch(module(), map()) :: {:ok, struct()} | {:error, Ecto.Changeset.t()}
  def dispatch(command_module, params) do
    changeset = command_module.changeset(params)

    if changeset.valid? do
      commit(command_module, changeset)
    else
      {:error, changeset}
    end
  end

  @spec query(module(), map()) :: {:ok, term()} | {:error, term()}
  def query(query_module, params), do: query_module.run(params)

  defp commit(command_module, changeset) do
    unique_fields = command_module.unique_fields()

    case UniqueCheck.reserve(changeset, unique_fields) do
      {:ok, changeset, _reserved} ->
        case Repo.insert(changeset) do
          {:ok, struct} ->
            {:ok, struct}

          {:error, changeset} ->
            UniqueCheck.release(changeset, unique_fields)
            {:error, changeset}
        end

      {:error, changeset} ->
        {:error, changeset}
    end
  end
end
```

## CQRS

`NewApiApp.CQRS.Dispatcher.dispatch/2` runs a command: build and validate a
changeset, reserve its declared unique-field groups in a short-term cache
(fast reject on a collision, and a race guard between the check and the
write landing), then insert. `NewApiApp.CQRS.Dispatcher.query/2` runs a
query — a direct pass-through, no caching.

A command module implements `NewApiApp.CQRS.Command`:

```elixir
defmodule NewApiApp.Accounts.CreateUser do
  @behaviour NewApiApp.CQRS.Command

  alias NewApiApp.Accounts.User

  @impl true
  def changeset(params) do
    %User{}
    |> Ecto.Changeset.cast(params, [:email, :org_id, :username])
    |> Ecto.Changeset.validate_required([:email, :org_id, :username])
    |> NewApiApp.CQRS.UniqueCheck.validate_unique_constraints(unique_fields())
  end

  @impl true
  def unique_fields, do: [[:email], [:org_id, :username]]
end
```

`validate_unique_constraints/2` names its DB constraints to match the
default name Ecto's own `unique_index/2` migration helper produces for the
same field list — declare the matching migration with no explicit `:name`:

create unique_index(:users, [:org_id, :username])
```

For UUIDv7 primary keys, declare on the schema:

```elixir
@primary_key {:id, Uniq.UUID, autogenerate: true, version: 7, type: :binary_id}
```

**Limitation:** `dispatch/2` only supports creating a new record
(`Repo.insert/1`) — a command whose changeset targets an existing record is
not supported in this version.
```

- [ ] **Step 1: Write the test file**

```elixir
defmodule Capstone.Integration.CqrsDispatchTest do
  @moduledoc """
  Exercises the full :cqrs dispatch path against a real Postgres: a
  successful create, a genuine concurrent race (proving the cache's atomic
  reservation serializes it), and the DB catching a duplicate once the
  cache no longer blocks it (proving the DB, not the cache, is the actual
  ground truth).

  The fixture schema, migration and command written here into the
  GENERATED project are NOT part of priv/meta/cqrs_component/ — capstone
  doesn't know a consuming project's schemas (see the CQRS plugin design
  spec's Testing section), so this lives entirely in this repo's own test
  suite and is never diffed by `mix capstone.plugin.derive`.
  """

  use ExUnit.Case, async: false

  alias Capstone.New.Bootstrap
  alias Capstone.New.Options
  alias Capstone.New.Shell

  setup do
    Mix.Local.append_archives()
    Mix.Task.reenable("new")
    Mix.Task.reenable("phx.new")

    dir = Path.join(System.tmp_dir!(), "cqrs-dispatch-#{System.unique_integer([:positive])}")
    File.mkdir_p!(dir)

    on_exit(fn -> File.rm_rf!(dir) end)

    {:ok, tmp_dir: dir}
  end

  @tag :toolchain
  test "dispatch: success, a concurrent race, and the DB catching what the cache no longer blocks",
       %{tmp_dir: tmp} do
    capstone_path = File.cwd!()
    name = "cqrs_dispatch"

    opts = %Options{
      name: name,
      app: :cqrs_dispatch,
      module: CqrsDispatch,
      base: :api,
      github_org: "acme",
      capstone: {:path, capstone_path},
      plugins: [:cqrs]
    }

    File.cd!(tmp, fn -> assert :ok = Bootstrap.run(opts, Bootstrap.defaults()) end)

    project = Path.join(tmp, name)
    write_fixture_migration!(project)
    write_fixture_schema!(project)
    write_fixture_command!(project)
    write_fixture_test!(project)

    Shell.cmd!(["test", "test/widget_dispatch_test.exs"], project)
    Shell.cmd!(["ecto.drop", "--quiet"], project)
  end

  defp write_fixture_migration!(project) do
    path = Path.join(project, "priv/repo/migrations/20260827000001_create_widgets.exs")
    File.mkdir_p!(Path.dirname(path))

    File.write!(path, """
    defmodule CqrsDispatch.Repo.Migrations.CreateWidgets do
      use Ecto.Migration

      def change do
        create table(:widgets, primary_key: false) do
          add :id, :binary_id, primary_key: true
          add :email, :string, null: false

          timestamps(type: :utc_datetime)
        end

        create unique_index(:widgets, [:email])
      end
    end
    """)
  end

  defp write_fixture_schema!(project) do
    File.write!(Path.join(project, "lib/cqrs_dispatch/widget.ex"), """
    defmodule CqrsDispatch.Widget do
      use Ecto.Schema

      @primary_key {:id, Uniq.UUID, autogenerate: true, version: 7, type: :binary_id}
      schema "widgets" do
        field :email, :string
        timestamps(type: :utc_datetime)
      end

      def changeset(widget, params) do
        widget
        |> Ecto.Changeset.cast(params, [:email])
        |> Ecto.Changeset.validate_required([:email])
        |> CqrsDispatch.CQRS.UniqueCheck.validate_unique_constraints([[:email]])
      end
    end
    """)
  end

  defp write_fixture_command!(project) do
    File.write!(Path.join(project, "lib/cqrs_dispatch/cqrs/create_widget.ex"), """
    defmodule CqrsDispatch.CQRS.CreateWidget do
      @behaviour CqrsDispatch.CQRS.Command

      alias CqrsDispatch.Widget

      @impl true
      def changeset(params), do: Widget.changeset(%Widget{}, params)

      @impl true
      def unique_fields, do: [[:email]]
    end
    """)
  end

  defp write_fixture_test!(project) do
    File.write!(Path.join(project, "test/widget_dispatch_test.exs"), """
    defmodule CqrsDispatch.WidgetDispatchTest do
      use CqrsDispatch.DataCase, async: false

      alias CqrsDispatch.CQRS.CreateWidget
      alias CqrsDispatch.CQRS.Dispatcher

      test "a successful create leaves the row in the database" do
        email = "widget-\#{System.unique_integer([:positive])}@example.com"
        assert {:ok, widget} = Dispatcher.dispatch(CreateWidget, %{email: email})
        assert widget.email == email
      end

      test "two concurrent dispatches for the same email: exactly one succeeds" do
        email = "race-\#{System.unique_integer([:positive])}@example.com"

        results =
          [Task.async(fn -> Dispatcher.dispatch(CreateWidget, %{email: email}) end),
           Task.async(fn -> Dispatcher.dispatch(CreateWidget, %{email: email}) end)]
          |> Enum.map(&Task.await(&1, 5_000))

        assert Enum.count(results, &match?({:ok, _}, &1)) == 1
        assert Enum.count(results, &match?({:error, _}, &1)) == 1
      end

      test "the DB unique index catches a duplicate once the cache no longer blocks it" do
        email = "expired-\#{System.unique_integer([:positive])}@example.com"
        assert {:ok, _widget} = Dispatcher.dispatch(CreateWidget, %{email: email})

        # Simulate the reservation having expired (or never existed, e.g.
        # after a node restart) — the cache no longer blocks a second
        # attempt, so this proves the DB's own unique index is the actual
        # ground truth, not the cache.
        key = {CqrsDispatch.Widget, [:email], [email]}
        :ok = CqrsDispatch.CQRS.Cache.delete(key, [])

        assert {:error, changeset} = Dispatcher.dispatch(CreateWidget, %{email: email})
        assert %{email: ["has already been taken"]} = errors_on(changeset)
      end

      defp errors_on(changeset) do
        Ecto.Changeset.traverse_errors(changeset, fn {msg, opts} ->
          Regex.replace(~r"%{(\\w+)}", msg, fn _, key ->
            opts |> Keyword.get(String.to_existing_atom(key), key) |> to_string()
          end)
        end)
      end
    end
    """)
  end
end
```
